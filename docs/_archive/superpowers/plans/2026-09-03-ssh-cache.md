# SSH 列表缓存 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 通过主进程配置缓存、页面缓存和并发请求去重，加速 SSH 主机列表加载而不降低安全校验强度。

**Architecture:** 将文件指纹缓存和解析职责封装在 `ssh-config-adapter`，将状态探测与配置快照缓存封装在 SSH service；renderer 通过独立的内存缓存模块提供 stale-while-revalidate 行为。所有缓存都只存在内存，并在 Host 配置变更或主动刷新时失效。

**Tech Stack:** Electron main process、React、TypeScript、Vitest、Node `fs.stat`/Promise。

---

### Task 2：主进程列表/状态缓存与请求去重

**Files:**
- Modify: `desktop-client/electron/services/ssh-service.ts`
- Test: `desktop-client/tests/electron/ssh-service.test.ts`

- [ ] **Step 1：写失败测试**
  - 断言相同 TTL 内连续 `listHosts()` 不重复执行 resolve、scanFingerprint、testBatch。
  - 断言并发 `listHosts()` 共享同一个 Promise。
  - 断言 `forceRefresh` 跳过状态缓存；成功的 trust/remove/upsert 使相关缓存失效。

- [ ] **Step 2：运行红灯测试**
  - 运行 `pnpm exec vitest run --config vitest.config.ts tests/electron/ssh-service.test.ts`。
  - 预期新增调用计数断言失败。

- [ ] **Step 3：实现最小缓存**
  - 在 service 内保存配置结果、状态结果和 in-flight Promise，缓存键使用 Host id/目标指纹。
  - 默认状态 TTL 使用 10 秒；提供 `listHosts({ forceRefresh?: boolean })` 给 IPC 主动刷新使用。
  - 避免缓存 rejected Promise；请求结束后清理 in-flight 引用。
  - Host 列表变化后清除相关状态缓存，不改变 `connect`/`openExternal` 的实时安全校验。

- [ ] **Step 4：运行绿灯测试**
  - 重跑 service 测试、SSH 相关测试、typecheck 和 `git diff --check`。

- [ ] **Step 1：写失败测试**

  - 测试页面首次加载无缓存，后续挂载立即使用缓存并触发必要的后台刷新。
  - 测试主动刷新绕过缓存，Host 变更操作后清理缓存。

- [ ] **Step 2：运行红灯测试**
  - 运行 `pnpm exec vitest run --config vitest.config.ts tests/ssh-host-cache.test.ts tests/ssh-page.test.ts`。
  - 预期新增缓存测试因模块不存在或页面未接线而失败。

- [ ] **Step 3：实现最小页面缓存**
  - 缓存 `SshListResult` 和时间戳，不缓存输入、终端内容或敏感字段。
  - 页面首次进入先读缓存；过期缓存先显示，再后台调用 `ssh.list()`。
  - 使用共享 in-flight Promise，避免 StrictMode 和重复挂载造成重复请求。
  - `load({ force: true })` 用于刷新和变更操作，成功后更新缓存；失败保留已有展示并显示错误。
