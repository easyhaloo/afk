# SSH 列表缓存设计

**日期：** 2026-09-03

## 目标

减少 SSH 页面重复进入、刷新和操作完成后的等待时间，同时保证配置文件变化、Host 状态变化和安全校验不会被长期缓存掩盖。

## 方案

采用两层内存缓存：

1. **主进程配置缓存**：`ssh-config-adapter` 按 `~/.ssh/config` 与 `~/.ssh/afk_hosts` 的文件指纹缓存解析结果。文件未变化时复用解析后的 Host/diagnostics；文件变化、添加或删除 Host 后失效。
2. **页面请求缓存**：renderer 侧保存最近一次 `ssh.list()` 结果和时间戳。页面重新挂载时先显示仍在有效期内的结果；过期时显示已有结果并后台刷新。相同时间的请求共享一个 Promise。

SSH 指纹扫描、known_hosts 校验和免密测试属于状态探测，使用短 TTL 缓存并支持主动刷新；不会因为页面缓存绕过主进程安全门禁。

## 页面行为

- 首次打开无缓存：显示现有加载状态并请求数据。
- 30 秒内重新进入：立即展示页面缓存，不阻塞页面；同时不发起重复请求。
- 超过 30 秒重新进入：先展示旧结果，再后台刷新。
- 点击刷新：强制刷新并替换缓存。
- 添加、删除、信任指纹、部署公钥后：清除页面列表缓存并重新加载。
- 缓存仅存在 renderer 内存，应用退出自动消失；不写入磁盘。

## 主进程行为

- 配置文件读取使用文件元信息指纹（存在性、mtime、size）；指纹相同则不重复读取和解析。
- 配置读取失败不复用旧结果，继续返回当前错误。
- 同一 adapter 实例内并发 `listHosts()` 请求共享一次文件读取/解析 Promise。
- 主机状态探测使用受控 TTL；主动刷新可以跳过状态缓存。
- `upsertManagedHost`、`removeManagedHost` 成功后清理配置缓存。

## 安全与一致性

- 不缓存私钥、密码、SSH 输入、PTY 输出或外部终端命令。
- `openExternal`、`connect`、`trust` 等操作仍由主进程实时校验 Host 和 fingerprint。
- 缓存结果保留 `configPath`、diagnostics 和 Host 状态的原有结构。
- 缓存读取/写入均为单线程内存操作，不改变现有 IPC 白名单和 sender guard。

## 验收标准

- 配置文件未变化时，连续列表请求不重复读取和解析配置。
- 配置文件变化后下一次列表请求返回最新 Host 和 diagnostics。
- 并发列表请求只执行一次底层读取/探测。
- 页面重复进入可立即展示缓存，主动刷新仍能拿到新结果。
- 变更操作不会继续显示已删除、未信任或旧配置 Host。
- 全量测试、typecheck、build 和 `git diff --check` 通过。
