# 工作项筛选与渐进加载优化设计

## 目标

优化桌面端全局工作项页面的筛选区和“显示更多”入口，解决筛选触发器文字换行、长仓库名溢出、下拉菜单过长以及加载按钮与列表割裂的问题，同时保持现有数据查询和每次加载 50 条的行为不变。

## 当前问题

- “全部来源平台”和“全部 Issue 来源”使用固定宽度矩形控件，中文标签会在窄宽度内换行，破坏工具栏对齐。
- Issue 来源数量较多时，下拉菜单会随全部选项无限增长，超出可视区域。
- 长仓库名在选项中强制换行，导致行高不一致并降低扫描效率。
- 来源列表缺少菜单内搜索，用户需要在长列表中滚动查找仓库。
- 当前“显示更多（50 / 110）”是一个孤立的普通按钮，与工作项列表缺少视觉连续性。

## 选定方案

### 流式筛选条

搜索框保持为筛选区的主要入口。Provider 和 Issue 来源筛选器改为紧凑的胶囊形触发器，并作为当前筛选状态显示在搜索框之后。

- 触发器使用单行布局，标签和值均不换行。
- 默认状态显示“来源 · 全部”和“Issue · 全部”；选中具体值后显示对应平台或仓库名。
- 长值在触发器中使用省略号截断，完整内容通过 `title` 提示提供。
- 胶囊使用弱边框和浅背景，打开、悬浮或键盘聚焦时沿用现有绿色强调色。
- 搜索框优先占据剩余空间；筛选器保持内容可读的最小宽度，不再通过窄固定宽度强制换行。
- 窄屏时搜索框独占一行，筛选胶囊在下一行自然换行。

### 下拉菜单

Provider 菜单保持短列表，不增加额外搜索框。Issue 来源菜单增加局部搜索能力。

- Issue 来源菜单宽度不小于触发器，并设置合理的最大宽度，避免覆盖过多列表内容。
- 菜单设置视口相关的最大高度，选项区域内部滚动，不允许菜单突破窗口底部。
- 菜单顶部提供“搜索 Issue 来源”输入框，仅过滤当前已经获得权限的来源列表，不触发远程请求。
- “全部 Issue 来源”固定保留在结果顶部，不受搜索关键字影响。
- 仓库选项保持单行，使用省略号截断超长名称；悬浮时通过 `title` 显示完整名称。
- 当前选项使用浅绿色背景、文字强调色和勾选图标表达，不依赖文字换行或高度变化。
- 搜索无结果时显示紧凑的空状态，不关闭菜单，也不改变当前筛选值。

## 行内继续加载

采用已确认的 C 方案，将大按钮替换为列表尾部的行内继续加载控件。

- 控件位于工作项列表之后，由左右细分隔线、剩余数量和“继续加载”动作组成。
- 左侧状态显示“还有 N 个”，其中 `N = 总数 - 当前可见数`。
- 动作显示“继续加载”及向下箭头，不再重复展示“50 / 110”格式。
- 整个动作区域保留足够的点击高度，而不是仅让文字本身可点击。
- 每次点击仍将可见上限增加 50 条；当剩余数量少于 50 条时，一次加载全部剩余项。
- 所有结果可见后，整个行内加载控件消失，不显示额外的“已全部加载”占位。
- 搜索、Provider 或 Issue 来源发生变化时，可见上限重置为 50 条。

## 组件边界

- `WorkItemsPage` 保持工作项查询、筛选值、可见数量和详情选择状态。
- 扩展现有 `SelectMenu` 的展示能力时，新增行为必须是可选配置，默认样式与现有 Backlog、SSH 和工作流调用方保持不变。
- Issue 来源菜单的本地搜索状态属于菜单组件，不进入共享 IPC DTO，也不影响服务端查询。
- 行内加载控件只改变工作项页面的呈现，不引入分页 API、无限滚动或新的持久化状态。
- 复用现有 Lucide 图标、CSS 变量和桌面端控制高度，不引入新的设计依赖。

## 无障碍与键盘操作

- 筛选触发器继续提供准确的 `aria-label`、`aria-haspopup` 和 `aria-expanded`。
- 下拉菜单使用 `listbox`/`option` 语义，当前项继续暴露 `aria-selected`。
- 菜单搜索框具有“搜索 Issue 来源”的无障碍名称。
- Escape 关闭菜单，点击外部关闭菜单；关闭后焦点返回对应触发器。
- 行内加载动作保留 `aria-label="显示更多工作项"`，便于兼容现有自动化测试和辅助技术。
- 颜色只用于加强状态，当前选项仍通过勾选图标和 `aria-selected` 表达。

## 测试方案

组件测试覆盖：

- 两个筛选器标签保持单行，并使用新的流式筛选样式。
- Issue 来源菜单可通过关键字过滤长来源列表。
- 搜索无结果时显示空状态，“全部 Issue 来源”仍可选择。
- 选择来源后菜单关闭，筛选结果和可见上限正确更新。
- 超过 50 条时显示“还有 N 个”和“继续加载”。
- 点击继续加载后增加最多 50 条，并更新剩余数量。
- 全部工作项可见后加载控件消失。

Electron E2E 覆盖：

- 工作项页面在常规桌面宽度下，搜索框与筛选胶囊无文字换行。
- Issue 来源菜单具有有限高度并可滚动，长仓库名不撑宽或增加选项行高。
- 行内继续加载控件位于列表末尾，点击后列表项目数增加。

## 非目标

- 不改为服务端分页或游标分页。
- 不使用滚动到底部自动加载，避免不可预期的数据追加和滚动位置变化。
- 不增加多选 Provider、仓库或状态筛选。
- 不改变全局工作项的数据模型、授权范围、来源采集方式或执行逻辑。
- 不统一重做应用内所有下拉菜单的视觉样式。

## 验收标准

1. 筛选触发器在常规和窄屏布局中均不发生文字换行或相互挤压。
2. Issue 来源下拉菜单限制高度、支持本地搜索，并正确处理长仓库名。
3. 选择 Provider 或 Issue 来源后，现有工作项筛选语义保持不变。
4. “显示更多”替换为带左右分隔线的行内继续加载控件，并准确显示剩余数量。
5. 每次继续加载最多增加 50 条，加载完成后控件消失。
6. 现有菜单关闭行为、键盘操作和无障碍属性保持可用。
7. 聚焦组件测试、Electron E2E、桌面端类型检查和生产构建通过。
