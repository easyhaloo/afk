# AFK Control 桌面端设计规范

本文档定义 `apps/desktop/` 的通用界面设计约束。新增页面、组件或交互，以及修改现有界面时，都应遵循这些规则。

## 1. 图标优先

- 当常见图标能够清楚表达按钮含义时，只显示图标，不再附加可见文字说明。
- 图标按钮必须提供准确的无障碍名称，例如 `aria-label`；需要补充提示时使用悬浮提示，不在界面中常驻说明文字。
- 同一种操作应使用一致的图标、尺寸和交互状态，避免在不同页面混用图标按钮与文字按钮。
- 无法仅靠图标准确理解、可能产生歧义或需要强调结果的操作，可以保留文字。

## 2. 添加操作

- 用于打开新增表单、创建弹窗或插入内容的“添加”入口，统一使用独立的 `+` 图标按钮。
- 添加入口不显示“添加”“新增”“创建”等可见文字，也不采用“图标 + 文字”的组合形式。
- 图标按钮仍须提供与上下文对应的无障碍名称，例如 `aria-label="添加工作项"`。
- 本规则只约束添加操作的入口；表单中的“保存”“创建”“取消”等提交或流程按钮可以保留文字，以明确操作结果。

## 3. Header 操作

- 页面或应用 Header 的右上角不放置全局刷新按钮。
- 数据更新优先通过页面加载、操作完成后的局部重载、状态订阅或自动同步完成，不要求用户手动刷新整个界面。
- 只有在特定数据视图确实需要手动重试或重新拉取时，才可在该视图的上下文内提供刷新操作；不得重新放回全局 Header。
- 上下文刷新若可由刷新图标清楚表达，应使用纯图标按钮，并提供无障碍名称。

## 4. 评审检查

提交桌面端界面改动前，至少确认：

- 添加入口是否只显示 `+` 图标。
- 可由图标清楚表达的操作是否移除了冗余文字。
- 图标按钮是否具有准确的无障碍名称。
- Header 右上角是否不存在全局刷新按钮。
- 必要的手动刷新是否位于对应数据视图内，而不是全局 Header。

## 5. 上下文选择

- 少量、高频且互斥的选项使用 `SegmentedControl`，可见选项直接切换，支持方向键、Home/End 与单一 Tab 停靠点。表单执行模式、主题、密度和常用状态采用此模式。
- 动态资源使用 `SelectMenu` 的搜索模式：匹配名称、身份和次级说明，显示当前选项、无结果与本次页面会话最近使用；方向键移动、Enter 选择、Escape 关闭并回到触发器。最近使用只属于展示状态，不保存业务记录或凭据。
- 多维、低频过滤通过 `FilterPanel` 的图标入口展开；条件即时生效，在页面保留可移除标签，并提供清除全部。点击外部或 Escape 收起，不能把过滤条件藏在关闭的面板中。
- 全局工作项的 Issue 来源和关联执行仓库仍是不同身份。仓库过滤不改变仓库关联；运行配置保留逐仓库 Base 分支和显式确认。
- SSH 筛选和表单复用共享选择器；终端选择保留专用应用图标。任何展示改动不得跳过指纹信任、自动降级连接或触发未经用户确认的远程操作。

### 生产落地顺序与边界

1. 为共享组件补充键盘、当前值、搜索、禁用、最近使用和条件移除测试，再接入工作项与本地 Backlog。
2. 接入工作流配置、SSH 表单、外观偏好，保留现有 IPC 与主进程校验。提供本地工作区选择及页面搜索导航。
3. 代码仓库、Agents、执行环境、运行中心和活动记录增加本地搜索；搜索历史不得把旧事件误当作最新运行状态。
4. 执行桌面包自己的 typecheck、test、build，并用独立端口、隔离 HOME 与测试专用的类型化 Runtime fixture 验证 Electron 页面操作。不得复用其他 worktree 的 Vite。生产 bundle 的冒烟测试加载实际主进程与 Worker；库存通过 application/provider facade 读取，工作项选择 UI 的 Electron 测试通过显式库存 IPC fixture 提供确定数据，Provider 服务契约由独立服务测试验证。

全页面 HTML 原型是视觉和交互方向，不是服务契约。全局工作项创建/编辑/复制/删除、任意工作流模板复制、容器执行环境选择、模拟验证/合并、活动导出和新增终端偏好等提案，不能通过移植原型内存状态假装生产能力；当前仅提供现有 API 支持的真实操作。主题仅提供共享契约中的浅色/石墨，不伪造尚未支持的系统主题。

共享外观变量由 `apps/desktop/src/control.css` 定义；选择组件样式位于 `apps/desktop/src/selection.css`，复用 `--afk-panel`、`--afk-text`、`--afk-muted`、`--afk-border`、`--afk-accent` 和 `--afk-scale`，不另建并行主题系统。

工作流实例沿用原型的紧凑列表与分区详情：左侧搜索、状态筛选和运行身份，右侧展示本次工作流快照、步骤状态与显式依赖，并可切换到运行日志。快照缺失时不使用当前模板补齐历史。实例、工作项和运行中心复用同一个日志组件，按审计记录顺序展示时间、事件、步骤与结果，支持搜索、异常筛选和展开字段。运行健康独立折叠展示，不能代替审计进度；日志和实例样式集中在 `apps/desktop/src/features/run-center/execution.css`，沿用共享主题与字号变量。

工作项的运行记录采用列表与详情分栏，仅在此 Tab 扩宽详情面板。面板限制在侧栏右侧、顶部栏下方的内容区，不使用全窗口遮罩；宽屏保留左侧工作项上下文，应用导航保持可操作。左侧按实际开始时间倒序展示时间、状态与已记录的摘要，右侧展示选中记录的信息、工作流操作与共享时间线；两栏独立滚动，轮询和分页保留用户选中项。启动记录与审计记录即使运行编号相同，也保持独立选择身份。面板实际宽度不超过 720px 时切换为列表或详情的单页视图，详情提供“返回运行记录”并恢复列表焦点；缺少审计数据的启动记录不生成推测时间线。界面验证保留包含侧栏、顶部栏与内容区的整窗截图。

共享搜索与分段选择在资源工具栏中对齐为 36px 基准高度；设置页的选择组保留卡片内边距。组合搜索框只在容器上绘制焦点环，不在内部输入框重复描边；键盘焦点仍须清晰可见。筛选面板使用标题、分隔线与单层选项列表建立层级，已选项和生效条件采用克制的强调色。石墨主题的选中态混合当前面板颜色，不使用浅色底与硬编码深色文字；动效遵循减少动态效果偏好。

工作流定义编辑器采用画布与配置栏的独立双列布局，配置栏可收起，不能覆盖节点或缩放控件。节点按真实 `dependsOn` 的依赖深度分列，同层并行步骤分行，顺序执行的 Agent 与系统步骤保持在同一行；节点类型分组不能改变依赖或执行条件。首次打开、窗口尺寸变化和自动整理时按画布的实际可见区域适配节点与分组标题。页面顶部保留唯一保存入口，移除底部模板信息栏；起点配置按执行环境、重试与超时分组，超时以分钟编辑并转换为原有毫秒字段。前置依赖使用可换行标签，执行条件紧跟标签放在同一区域，不重复展示箭头和当前节点名称。样式集中在 `apps/desktop/src/features/workflows/workflow-studio.css`，沿用共享主题、手绘边角和硬阴影；项目模板中的真实分叉与汇合只按现有只读契约展示，不加入原型示例步骤。
