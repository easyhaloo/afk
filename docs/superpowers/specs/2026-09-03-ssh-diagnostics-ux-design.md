# SSH 配置诊断提示优化设计

## 背景

SSH 页面当前把解析器返回的每一条诊断直接转换成字符串，并使用分号拼接展示。当多个 Host 含有同一种未识别配置项时，页面会出现长串重复文本，用户难以判断问题数量、影响范围和配置来源。

## 目标

- 将重复诊断合并为紧凑、可扫描的摘要。
- 让用户能够看到受影响的 Host 别名和配置文件路径。
- 保留不同诊断类型的严重程度，不隐藏真正的配置问题。
- 不改变 SSH 配置解析和连接安全行为。
- 为诊断聚合逻辑增加独立单元测试。

## 方案

### 结构化诊断

在 `SshDiagnostic` 中增加可选的 `hostAlias` 字段。解析 Host 块时，`unknown-directive` 和 `malformed-directive` 诊断携带当前 Host 别名；非具体 Host 的诊断不携带别名。现有诊断字段保持兼容。

### 前端聚合

在 SSH 页面增加纯函数，将诊断按 `severity + code + message 模板 + path` 聚合，并收集 Host 别名。聚合结果包含：

- 诊断级别；
- 诊断代码；
- 展示文案；
- 配置路径；
- 出现次数；
- 受影响 Host 别名列表。

页面默认显示一条摘要，例如“SSH 配置提示 · 18 项”，下方按类型显示“未识别配置项 · 18 个 Host”。受影响 Host 默认只显示前几个，其余通过“展开详情”查看，避免页面被长文本撑开。

### 视觉与交互

- 诊断区域采用独立的标题、数量和列表布局，不再使用一行连续文本。
- 警告色保持低饱和，并与错误提示、成功提示区分。
- 详情使用原生 `details/summary`，不引入额外状态管理。
- 配置路径使用等宽字体显示，Host 别名使用标签样式显示。
- 没有可关联 Host 的诊断仍能正常展示，并显示诊断原文。

## 非目标

- 不在本次工作中支持所有 OpenSSH 指令的语义解析。
- 不改变系统 `~/.ssh/config` 或 AFK 管理配置文件的写入方式。
- 不新增远程连接、指纹校验或私钥管理能力。

## 验收标准

1. 同一类诊断不再重复拼接成一行长文本。
2. 页面能显示诊断总数、问题类型、配置路径和受影响 Host。
3. 多种诊断同时存在时，每种诊断独立成组，严重程度样式正确。
4. 无 Host 关联的诊断不会导致渲染异常。
5. 诊断聚合单元测试覆盖重复项、不同路径、不同严重程度和无 Host 诊断。
6. `pnpm test`、`pnpm typecheck` 和 `pnpm build` 通过。
