# SSH 托管主机与 OpenSSH 配置解耦设计

## 目标

允许 AFK 管理主机使用中文显示名称，同时避免把 AFK 的显示别名当作
OpenSSH `Host` 别名。AFK 托管主机由 AFK 保存和管理，OpenSSH 只在连接
时接收真实主机地址及结构化连接参数。

## 核心模型

- `alias` 保留为 AFK 显示名称，可包含中文、空格及其他普通显示字符；
  它不再作为 OpenSSH `Host` 名称、命令参数或配置块定位键。
- 每个托管主机使用稳定的 AFK 主机 ID。主机名称变化不会改变该 ID，
  也不会导致旧 OpenSSH 配置块迁移。
- `hostname` 保存真实连接地址，支持 IP 地址或可解析的 DNS 主机名。
- `port`、`user`、`identityFile` 和跳板机信息作为连接 DTO 传入 SSH
  命令适配器，由适配器生成固定的 argv 参数。

示例：

```ts
{
  id: "managed:<stable-id>",
  alias: "kg演示",
  hostname: "172.16.0.241",
  port: 22,
  user: "root",
  identityFile: "~/.ssh/id_ed25519"
}
```

## 配置边界

- 新增或编辑 AFK 托管主机不写入 `~/.ssh/afk_hosts`，也不维护
  `~/.ssh/config` 的 AFK `Include`。
- AFK 托管配置保存到 AFK 自己的配置文件；该文件只保存非敏感的主机
  参数和稳定 ID。部署密码继续由系统安全存储管理。
- 系统来源主机仍可从用户现有 `~/.ssh/config` 读取，作为只读外部配置。
  系统来源主机的 OpenSSH alias 仅用于兼容既有配置，不影响 AFK 托管主机。
- 不自动迁移或删除用户已有的 `~/.ssh/config`、`~/.ssh/afk_hosts` 内容。

## 连接数据流

- 解析托管主机时不再调用 `ssh -G <alias>`。
- 指纹扫描直接使用 `hostname` 和 `port`。
- 免密测试使用结构化参数连接真实地址，并附加 `BatchMode=yes`。
- 内置终端、外部终端和公钥部署都使用同一套结构化连接参数。
- OpenSSH 参数通过 argv 数组传递，不拼接不可信字符串或远程命令。
- JumpServer 跳板机仍可使用现有、合法的 OpenSSH 跳板目标；托管目标
  本身不依赖中文 `Host` alias。

## 校验与兼容性

- AFK 显示名称只做非空、长度、NUL 字符等通用文本校验，不套用
  OpenSSH alias 的 ASCII 限制。
- 主机地址、端口、路径和跳板机参数继续在主进程校验。
- 现有 `managed:<旧 alias>` ID 需要兼容读取；迁移到稳定 ID 时保留
  映射，避免已有凭据和选中状态失效。
- 现有 ASCII 托管名称继续正常显示和连接。
- 系统配置中的通配符、非法或无法解析 Host 继续生成诊断，不作为 AFK
  托管配置写回。

## 错误处理

- 中文名称保存成功后，任何 SSH 连接错误都应报告真实连接目标的失败原因，
  不再出现 `SSH 主机别名无效`。
- 配置持久化失败时不启动连接，也不修改部署凭据。
- 目标地址缺失、端口非法或跳板机配置无效时，在主进程边界拒绝请求。

## 测试

- 校验：中文名称可通过；NUL、空名称和超长名称被拒绝；OpenSSH alias
  限制不再应用于 AFK 显示名称。
- 配置：托管配置不写入 `~/.ssh/afk_hosts`，重启后可读回中文名称，
  稳定 ID 和凭据目标保持不变。
- 命令适配器：指纹扫描、免密测试、PTY、外部终端和部署均接收真实
  hostname，并生成正确 argv。
- 服务：托管主机不调用 `ssh -G <中文名称>`；缓存失效和状态更新正常。
- 页面：中文名称可新增、编辑、搜索、显示和连接；错误提示不再显示
  `SSH 主机别名无效`。
- 回归：系统来源的既有 OpenSSH alias 读取和连接行为保持不变。
