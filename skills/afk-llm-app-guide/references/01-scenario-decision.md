# Agent / Workflow 场景决策框架

## 核心判定维度

| 维度 | Workflow + HITL | Agent + 边界约束 |
|------|----------------|-----------------|
| 确定性需求 | 高（输出错误代价高） | 低（允许不确定性） |
| 步骤可枚举性 | 能用固定步骤描述 | 无法预先穷举 |
| 影响范围 | 团队/系统级 | 个人/局部 |
| 失败代价 | 不可逆、高 | 可接受 |
| 成本/任务 | $0.01–$0.10 | $0.30–$2.00 |
| 延迟 | 1–10秒 | 15–90+秒 |
| 适用场景 | 合规/审批/高风险操作 | 探索/抽取/自适应 |

## 决策检查清单

```
Step 1: 结果能精确描述吗？
├── YES → 强确定性场景，Workflow优先
└── NO  → 进入Step 2

Step 2: 失败后代价是什么？
├── 高（不可逆）→ 必须Workflow + HITL必经节点
└── 低 → 进入Step 3

Step 3: 需要从海量信息中提取相关内容吗？
├── YES → Agent为主，Workflow作为工具
└── NO  → 进入Step 4

Step 4: 路径需要根据中间结果动态调整吗？
├── YES → Agent
└── NO  → Workflow
```

## 典型场景映射

### 强确定性端（Workflow + HITL必经）

```
- 合规检查（规则引擎）
- 审批流（多级审批链）
- 权限变更（用户角色/权限调整）
- 财务操作（报销/支付）
- 发布流程（构建/部署/回滚）
- 高风险工具调用（删除/force push）
```

### 高自主性端（Agent + 边界约束）

```
- 海量文档信息提取
- 根因分析
- 代码改写建议
- 开放域问答
- 多工具组合探索
```

### 混合场景（交替运行）

```
典型流程：
  Agent（理解意图）→ Workflow（合规检查）→ Agent（生成方案）
  → HITL（人工确认）→ Workflow（执行）
```

## 演化路径

```
阶段1: 纯Workflow
  稳定、可预测、固定步骤
       ↓
阶段2: Workflow + 条件分支
  规则路由，但分支复杂到难以维护
       ↓
阶段3: 局部Agent
  单一领域内自主决策
       ↓
阶段4: Multi-Agent协调
  Supervisor/Router/Handoff模式
```

**不要跳跃阶段** — 每个演化都是业务复杂度自然驱动。

## Agent vs Workflow 本质关系

```
Workflow = Agent的编译形态
Agent = Workflow的运行时形态

同一步骤，两者都是：
  - 外部视角（系统设计者）→ 固定路径 → Workflow
  - 内部视角（运行时）→ LLM决定下一步 → Agent
```

## 检查清单

```
□ 任务结果能精确描述吗？
□ 失败代价是否不可逆？
□ 需要从海量信息中提取吗？
□ 路径需要动态调整吗？
□ 当前落在哪个演化阶段？
□ 从阶段到下一阶段的触发条件是什么？
```
