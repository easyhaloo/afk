# HITL 量化设计

## 核心量化问题

```
Q1: 在哪里插 checkpoint？  → Checkpoint密度
Q2: 什么时候触发暂停？   → 介入阈值
Q3: 值不值得介入？       → 介入成本 vs. 风险降低
```

## Checkpoint 密度设计

### 判定公式

```
Checkpoint必要性 = f(不可逆性 × 影响范围 × 置信度需求)

高 × 高 × 高 → 强制定checkpoint，不可绕过
```

### 决策表

| 情况 | Checkpoint密度 |
|------|--------------|
| 写文件/发布/删除 | 必然checkpoint |
| 只读查询/无状态计算 | 可无checkpoint |
| 涉及权限变更 | 必然checkpoint |
| 可逆操作（有回滚） | 可降低密度 |

## 替代置信度信号

logprob在很多场景不可得（国内模型/封闭API），使用工程化信号：

| 信号类型 | 采集方式 | 适用场景 |
|---------|---------|---------|
| Schema校验 | JSON.parse/类型检查 | 输出格式敏感 |
| 长度异常 | token计数 | 输出截断/敷衍 |
| 关键词命中 | 正则/关键词匹配 | PII/风险词 |
| 拒答模式 | "无法"/"不确定"检测 | 能力边界 |
| 响应延迟 | 时间戳对比 | 跳过推理 |

### 分层置信度评估

```
高置信度：
  ✓ Schema校验通过
  ✓ 长度正常
  ✓ 无风险词命中
  ✓ 无拒答模式
  → 自主通过

低置信度：
  ✗ Schema校验失败
  ✗ 长度严重异常
  ✗ 命中核心风险词
  ✗ 出现拒答
  → 必须HITL或降级
```

## 阈值设计

### 阈值类型

```
高风险（必须介入）：
  - 命中 > 0 条高风险规则
  - 操作对象是生产系统
  - 涉及金额 > X

中风险（条件介入）：
  - Schema校验失败
  - 模型置信度 < 0.7
  - 涉及首次出现的新实体

低风险（可选介入）：
  - 用户主动要求审核
  - 系统处于学习期
  - 批量操作
```

### 成本最优阈值

```
净收益 = (不介入错误率 - 介入后错误率) × 错误损失 - 介入成本

当净收益 > 0 时，介入是值得的
```

### 自适应阈值

```
初始：专家经验设定
     ↓
运行：收集 (输入特征, 自主决策, 人工override) 三元组
     ↓
训练：定期用override数据训练触发分类器
     ↓
更新：分类器预测介入必要性 > 0.5 时触发
```

## Checkpoint 放置检查清单

```
Node: [节点名称]
├── 不可逆操作？
│   ├── YES → 必须checkpoint
│   └── NO  → 继续
├── 影响范围？
│   ├── 个人 → 可选
│   ├── 团队 → 建议
│   └── 系统 → 必须
├── LLM错误最坏结果？
│   ├── 可接受 → 可选
│   └── 不可接受 → 必须
└── 介入成本 vs. 风险降低？
    ├── 成本 > 收益 → 监控为主
    └── 成本 < 收益 → 设置checkpoint
```

## 监控指标

| 指标 | 目标 |
|------|------|
| 自主通过率 | 越高越好 |
| 人工介入率 | 与风险匹配 |
| override率 | 越低越好 |
| 介入响应时间 | 越短越好 |
| 因介入避免的损失 | 可量化 |

## 检查清单

```
□ 不可逆性 × 影响范围 × 置信度需求 的乘积是多少？
□ 有哪些可采集的置信度信号？
□ 介入净收益是否 > 0？
□ 是否需要自适应阈值机制？
□ 监控指标是否完整？
```
